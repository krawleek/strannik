## Стек и среда

| Компонент | Конфигурация репозитория |
|---|---|
| Flutter / Dart | Локально проверены Flutter 3.47.5, Dart 3.13.4; `pubspec.yaml` требует Dart `^3.13.4` |
| Android | `applicationId` / namespace `ru.strannik.strannik`, minSdk 26 (Android 8.0) |
| Версия приложения | `1.0.0+1` в `pubspec.yaml`; CLI может переопределить build name / number |
| Android SDK | compileSdk и targetSdk берутся из установленного Flutter SDK, не закреплены числом в проекте |
| Gradle / AGP / Kotlin | Wrapper 9.3.1, AGP 9.1.0, Kotlin plugin 2.4.0 |
| Java | Android-код компилируется с target 17; для JVM запуска Gradle используйте совместимую установленную JDK, в предложении CI — Temurin 21 |
| Хранилище | `sqflite` 2.4.4 по ограничению зависимостей, SQLite schema v6; точные разрешённые версии — `pubspec.lock` |
| Защита PIN | `cryptography`, PBKDF2-SHA256, случайная соль; default 210000 итераций |
| Тесты | `flutter_test`, `integration_test`, `sqflite_common_ffi` |
| Визуальный слой | Manrope 600/700/800, локальные PNG и общие Flutter-компоненты |

Новых зависимостей для документации не добавлено. Backend, Firebase и обязательная регистрация не используются.

## Структура

```text
lib/
├── main.dart                  запуск, ориентация, edge-to-edge, повтор открытия при ошибке
├── app/                       сборка сервисов, feedback, настройки, экранное время
├── core/                      Result/Failure, часы и ID
├── content/                   каталог, экономика, русские тексты, сценарии уроков
├── domain/
│   ├── models/                Wallet, Pet, BudgetAllocation, цели, прогресс
│   ├── repositories/          интерфейсы и UnitOfWork
│   └── services/              правила обучения, экономики, магазина, стадий и PIN
├── data/
│   ├── local/migrations/      последовательные миграции v1…v6
│   ├── repositories/          SQLite-адаптеры и настройки
│   └── security/              хеширование PIN
└── presentation/
    ├── app/                   HomeRuntime, StrannikApp, AppShell
    ├── foundation/            цвета, Manrope, размеры, feedback scope
    ├── components/            кнопки, навигация, ввод PIN, питомец
    ├── onboarding/            знакомство и согласие взрослого
    ├── home/                  Дом и действия питомца
    ├── bank/                  план бюджета, цель и история
    ├── store/                 магазин и шкаф
    ├── learning/              карты тем и интерактивные задания
    ├── stages/                карта и подтверждение переходов
    └── profile/               детский профиль и родительский раздел
assets/                        локальные иллюстрации, шрифты, иконки
android/                       Android host, манифест, Gradle, платформенные каналы
test/                        domain/data/widget-тесты
integration_test/, test_driver/ Android integration-сценарии
```

`HomeRuntime.open()` загружает встроенный каталог, открывает БД и создаёт сервисы / контроллеры. `StrannikApp` выбирает онбординг или Дом по сохранённому флагу. `AppShell` переключает разделы через `AppDestination`; это локальная навигация без API-маршрутов.

Контроллеры публикуют состояние через ChangeNotifier; UI использует ListenableBuilder и стандартный Flutter state. Нового внешнего state-management framework нет. Виджеты вызывают сервисы; игровые правила не дублируют SQL.

## Хранение и транзакции

База `strannik.db` находится в Android databases directory. Каталог `lib/content/seed/development.json`, несмотря на имя, сейчас загружается обычным приложением. Он содержит определения товаров и заданий, а не пользовательские деньги; чтение файла не заселяет сохранение и не завершает онбординг.

SQLite хранит профиль, salted PIN credential и блокировку, питомца / skin / XP / стадию, Wallet, бюджет, две модели целей, инвентарь, историю операций, попытки и завершения заданий, финал темы, периоды и события, настройки, подсказки, экранное время.

`LocalDatabase.run()` оборачивает операцию в transaction и выдаёт `Success` / `Rejected`. Баланс, история и инвентарь покупки коммитятся вместе. Аналогично устроены награды и переходы. Уникальные индексы и operation keys ограничивают дубли. Включены foreign keys и secure deletion. Миграции добавляют поля / таблицы и сохраняют стабильные ID задач; v5 переводит старый `adaptOnEarth` в `spaceTaxi` без обнуления Wallet.

Сессия родителя живёт в памяти 10 минут; завершение сессии не меняет PIN. Три неверных PIN блокируют проверку на 5 минут, блокировка сохраняется. Возврат к ребёнку / фон завершает авторизацию. Полный сброс и удаление — разные подтверждаемые операции: сброс сохраняет имя и PIN, удаление очищает и их.

Шаги уроков сохраняются; черновик онбординга — нет. Экранное время пишется checkpoint-ами примерно каждые 15 секунд; force kill может потерять последний интервал статистики. Это не потеря всей игры.

## Android и offline

Иллюстрации и контент упакованы локально; основная игра не вызывает сеть. Android Auto Backup отключён. В main manifest запрошены уведомления и вибрация; камера, микрофон и геолокация не нужны. Debug/profile manifests отдельно включают INTERNET для Flutter tooling — это не игровой backend.

`MainActivity.kt` содержит каналы уведомлений и открытия письма поддержки. Подарок родителя может вызвать локальное уведомление при включённой настройке и разрешении Android; расписания напоминаний нет. Письмо поддержки открывает внешнее почтовое приложение, без автоматической отправки. Учебные мошеннические письма не используют этот канал.

SFX используют системный click, haptics — платформенную вибрацию. MusicOutput остаётся no-op, музыкальные треки не поставляются. Настройки сохраняются независимо от наличия полноценного звука.

## Дизайн и доступность

Базовый макет 360×800; SafeArea и IME insets, прокрутка длинных экранов, Semantics для основных интерактивных элементов, общие токены `app_tokens.dart`. В widget-тестах есть узкие экраны и text scale 1.3. Это частичное покрытие, не сертификат доступности или доказательство отсутствия overflow на всех Android-устройствах. Отдельные экраны содержат локальные цвета и размеры вне общих токенов.

## Локальная проверка и сборка

```bash
flutter doctor -v
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

Для Android integration выберите один сценарий и отдельное тестовое устройство:

```bash
flutter drive --driver=test_driver/stage_two_driver.dart --target=integration_test/stage_two_flow_test.dart -d <device-id>
```

Не запускайте integration-сборку как готовую демоверсию для жюри. Release-подпись и подготовка файла: [RELEASE_READINESS.md](RELEASE_READINESS.md). Команды не являются заявлением об их успешном выполнении: [результаты](DOCUMENTATION_AUDIT.md#проверки).
