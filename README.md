# Странник

Локальное Flutter-приложение для Android 8.0+ (API 26). На этом этапе реализован
архитектурный фундамент: модели, SQLite, игровые операции и тесты. Существующий
демонстрационный экран Flutter и его smoke test сохранены; финальный UI,
навигация и подключение игровых сценариев к экранам — следующий согласуемый этап.

## Структура

- `lib/app/bootstrap.dart` — сборка сервисов через конструкторы, открытие базы.
- `lib/core/` — типизированные результаты, проверки чисел, часы и генератор ID.
- `lib/domain/models/` — профиль, PIN-настройки, питомец, экономика, инвентарь,
  учебные задания/прохождения, события и периоды. Без Flutter и SQL.
- `lib/domain/repositories/` — небольшие контракты хранилищ, локального контента,
  хеширования PIN и транзакционной границы.
- `lib/domain/services/` — onboarding, экономика, накопления, покупки, взаимодействия
  с питомцем, обучение, сюжет, периоды, родительский доступ, demo и сброс.
- `lib/data/local/` — SQLite и последовательные миграции.
- `lib/data/repositories/` — transaction-scoped SQL-адаптеры и mapping моделей.
- `lib/data/security/` — PBKDF2-SHA256 с индивидуальной случайной солью.
- `lib/content/` — чтение локального JSON, русское форматирование и отдельный seed.
- `test/domain/`, `test/data/` — правила экономики, ограничения и реальные
  SQLite-транзакции без UI/эмулятора. Исходный `test/widget_test.dart` сохранён.

Пустые папки будущих features не создавались. Пакеты состояния UI и DI не добавлялись.

## Зависимости

Runtime: `sqflite` — SQLite на Android; `path` — путь базы;
`cryptography` — salted hash PIN. Dev: `sqflite_common_ffi` — SQLite в тестах
на рабочей машине. Остальные прямые зависимости проекта сохранены.

## Инициализация и контент

`openGameDatabase()` открывает `strannik.db` в приватном каталоге баз приложения.
Вызывать после `WidgetsFlutterBinding.ensureInitialized()`. Создание
`GameServices(unitOfWork: database, content: content)` связывает сервисы.
Владельцу жизненного цикла нужно закрыть `LocalDatabase` через `close()`.

`LocalContentRepository.fromJson(...)` принимает только локальный документ:
никакой сети, загрузки удалённого контента или серверной зависимости нет.
Будущий bootstrap UI сможет передать текст из Flutter asset bundle.
В текущем `main.dart` база и seed автоматически не запускаются.

`lib/content/seed/development.json` — **только примеры для разработки/тестов**:
товары, четыре материала, четыре темы, четыре одноразовых задания и одно
дополнительное повторяемое задание. Цены, XP, требования стадий и unlock накоплений
после `theme2` — тестовые значения, не утверждённый баланс продукта.
`contentReference: placeholder` не содержит полноценного урока. Seed не включён
в production assets и не создаёт пользовательское состояние. Объекты
`SavingsGoal` создаются сервисом; тесты содержат примеры накопительных целей.

Контент проверяется на версию схемы, отрицательные суммы, дубликаты и ссылки.
Идентификаторы материалов и типов заданий расширяемые; новый тип задания
потребует будущего обработчика/экрана. У заданий есть `oneTime`/`repeatable` и
`repeatRule: newCompletedAttempt`; иных правил повторения в MVP нет.
Стабильные ID заданий и их reward policy нельзя произвольно менять в опубликованном
контенте без миграции прогресса. Пользовательские тексты — русские, технические
имена — английские. `formatFira` выдаёт «1 фира», «2 фиры», «100 фир»; домен не
содержит локализованных ошибок и форматирования валюты.

## Хранение и транзакции

Схема SQLite версии 1 создаётся миграцией `schema_v1.dart`. Будущие миграции
добавляются последовательно в `LocalDatabase.migrate`, без удаления существующей
базы. Downgrade не уничтожает данные, а отклоняется. Включены foreign keys и
`secure_delete`; пользовательское состояние не хранится одним JSON blob.

Таблицы:

- `child_profile`, `parent_settings`, `pet`;
- `wallet`, `budget_allocation`, `big_goal`, `savings_goals`;
- `inventory_entries`, `transactions`;
- `learning_progress`, `learning_attempts`;
- `game_periods`, `progress_events`, `period_summaries`, `period_resource_summaries`;
- `app_state`, `tooltip_flags`.

Для MVP — один локальный профиль и одна текущая накопительная цель, в том числе
после достижения её суммы. XP и реальная стадия находятся у питомца; количества
материалов — только в инвентаре. Каталоги не дублируются в базе. Статусы накоплений
и completion тем вычисляются по сохранённым данным. Родительское поощрение —
запись истории с `type/source = parentReward`, суммой и датой.

`UnitOfWork.run` — тонкая обёртка SQLite transaction. Сервис получает связанные с
одной транзакцией repositories. SQL и низкоуровневые записи не должны вызываться
из widgets: игровые изменения выполняются через сервисы. Успех возвращается
только после commit. Доменное отклонение или ошибка SQLite откатывают все записи;
ошибка БД превращается в `PersistenceFailure`.

Деньги, XP, цены и количества — целые неотрицательные значения, ограниченные
`maxGameValue`. Проверки domain дополняются CHECK/UNIQUE в SQLite. Баланс и история
меняются вместе. Уникальные ключи защищают стартовую и учебные награды;
параллельные покупки выполняются последовательно внутри транзакций.

## Защищённые игровые правила

- Onboarding фиксирует питомца и выдаёт ровно 100 фир один раз за игру. Имя/skin
  питомца после этого неизменяемы. Ник профиля можно менять.
- Покупки расходуют только доступный баланс и не дают XP. Аксессуары и игрушки
  не дублируются; treats и материалы хранят количество.
- Бюджет — намерение: проверяется при сохранении, не блокирует покупки и не
  переписывается после них. `shortfall` вычисляет расхождение с балансом.
- Внесение в накопления уменьшает кошелёк, снятие возвращает средства.
  Превышение цели запрещено. Статус `completed` возвращается в `active` после
  снятия. Создание второй цели запрещено, пока текущая существует. Завершение/
  удаление отдельной цели через UI оставлено на следующий этап.
- Накопления открываются по теме из контента либо в demo. Уже накопленные
  средства можно снять после выключения demo, даже если обычный unlock ещё не
  достигнут; деньги не оказываются заблокированными.
- Treat расходуется вместе с выдачей XP. Активная игрушка выдаёт XP один раз за
  конкретный игровой период; переэкипировка не снимает ограничение.
- Подтверждённая большая цель неизменяема. Для перехода нужны XP и ресурсы из
  конфигурации конкретной цели/стадии. Материалы списываются, стадия и событие
  сохраняются атомарно. Опциональный `workXp` привязан к этой фактической работе
  с ресурсами, а не к покупке или свободному вызову начисления XP.
- Одноразовое задание награждает один раз. Повторяемое — за каждое **новое**
  завершённое прохождение; повторный callback того же `attemptId` не награждает.
  Повторный `beginTask` возвращает незавершённую попытку. Ошибка ответа не
  штрафует, не закрывает попытку и позволяет повторить её. Успешность ответа
  передаёт будущий обработчик урока; полные уроки сейчас не реализованы.
- Дополнительные повторяемые упражнения доступны после начала игры, не входят
  в обязательный набор completion темы и не требуют cooldown/daily/streak.

## Периоды и статистика

Стартовое начисление учитывается в `firstMoney`. Последняя награда темы входит
в завершаемый период; затем в той же транзакции фиксируется summary, закрывается
период и открывается следующий. Пятый период остаётся текущим.

`receivedFira` — внешние для кошелька игровые начисления, `spentFira` — покупки,
`savedFira` — внесения минус снятия за период (может быть отрицательным),
`remainingFira` — доступный баланс на границе периода. Перемещения накоплений
не считаются новым доходом/расходом. XP и полученные материалы считаются по
`ProgressEvent`; snapshot включает реальную стадию, большую цель и остатки
материалов. Закрытый summary хранится неизменным, текущий вычисляется по запросу.

В demo темы можно проходить вне очереди: завершение будущей темы само по себе
не закрывает предыдущие периоды. Когда текущая обязательная тема завершена,
сервис последовательно закрывает уже выполненные темы; такой demo-сценарий
может создать промежуточный период нулевой длительности. Награды остаются в
периоде, в котором фактически получены.

## PIN, demo и сброс

PIN — четыре ASCII-цифры. Хранится PBKDF2-SHA256 (210000 итераций, 16 случайных
байт соли, 32 байта результата), а не открытое значение. После пяти неверных
попыток действует 30-секундная блокировка; счётчик и срок сохраняются в SQLite.
Тесты снижают стоимость KDF явной инъекцией, production default не меняется.
Успешная проверка сбрасывает счётчик. Родительские начисления, смена PIN, demo
и удаление данных проверяют PIN в сервисе, а не только в будущих экранах.
Это локальный барьер от случайного входа, не серверная авторизация.
Облачного восстановления нет; времени доверяем локальному устройству.

Demo использует ту же базу. `demoStage` — отдельный override, реальные XP,
материалы и стадия не меняются. Выключение demo очищает override. Экономика и
уникальность наград остаются обычными. Учебный/финансовый прогресс, сделанный
в demo, сохраняется в общей базе: отдельной demo-игры нет.

`resetProgress`/`resetDemoProgress` очищают игру, сохраняют профиль/ник и PIN,
снимают `onboardingCompleted`, выключают demo. Повторный onboarding начинает
новую игру. `deleteAllData` также удаляет профиль и PIN; остаются только пустые
системные значения первого запуска. Не добавлены обход PIN или облачный recovery.

## Android и приватность

`minSdk = 26` и package name `ru.strannik.strannik` сохранены. Никаких новых
аппаратных разрешений, аккаунтов, сетевых сервисов, аналитики или реальных
платежей не добавлено.

Auto Backup отключён минимальными штатными средствами: `allowBackup="false"`,
`fullBackupContent="false"`; для Android 12+ `data_extraction_rules.xml`
исключает пользовательские данные из cloud backup и device transfer.
Это учитывает то, что `allowBackup` само по себе может не запрещать перенос
между устройствами у отдельных производителей. См.
[документацию Android](https://developer.android.com/identity/data/autobackup).
Никакие дополнительные backup-пакеты не используются.

публикация в RuStore на этом этапе не выполняются.
